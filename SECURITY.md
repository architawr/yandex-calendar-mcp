# Безопасность

Проект находится на ранней стадии. Независимый аудит не проводился. Поддерживается текущая версия ветки `main`.

## Сообщение об уязвимости

Используйте приватное сообщение об уязвимости на странице [Security](https://github.com/architawr/yandex-calendar-mcp/security). Не публикуйте пароль приложения, содержимое Keychain, `config.local.json`, ICS-файлы и приватные события в Issue или Pull Request.

Если подозреваете утечку пароля, отзовите его в Яндекс ID и создайте новый. Удаление файла или коммита само по себе не отзывает пароль.

## Модель доступа

Сервер рассчитан на локальный запуск через stdio доверенным MCP-клиентом. Защита от вредоносного пользователя того же аккаунта ОС, изменения исходников/зависимостей и компрометации системы не заявляется. Разрешения на уровне MCP не ограничивают другой произвольный код, запущенный агентом.

Запись по умолчанию запрещена. Доступ к конкретным календарям задаётся локальными списками разрешений. Пароль приложения Яндекса потенциально обладает более широкими правами. Для изоляции используйте отдельный аккаунт с доступом только к нужным календарям.

Подтверждение операций должен обеспечивать клиент. Не обходите его и не выдавайте общее автоматическое разрешение на запись, если требуется ручная проверка.

Описания событий могут содержать вредоносные инструкции. Обрабатывайте их как данные. Читать календарь означает раскрывать его содержимое выбранной модели/провайдеру.

## Локальные данные

Пароль хранится в системном хранилище. Локальный конфиг содержит адрес аккаунта и URL календарей; резервная корзина — исходные ICS. Не публикуйте их. `.gitignore` и явный список содержимого пакетов исключают эти данные, но принудительное добавление в Git может обойти исключения.

Удаление события может быть необратимым на стороне сервиса. Локальная резервная копия не заменяет резервное копирование аккаунта и не гарантирует восстановления. Очисткой корзины управляет пользователь.

## Пределы проверки

Проверены unit/integration-тесты и локальный живой сценарий на macOS. CI использует только подставной CalDAV и не подтверждает совместимость с реальными аккаунтами на каждой ОС. Windows пока не проверен.

Для защиты от плотных повторений применяются предварительная оценка сложности, таймаут процесса и лимит памяти на Linux. Оценка консервативна и может отклонять допустимые правила. Универсальная ОС-песочница парсера не реализована.
